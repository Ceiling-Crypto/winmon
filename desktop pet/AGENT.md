# 桌宠 Agent / 动作包 / 全屏漫游（设计稿）

> 状态：**本地行为层已实现，动作包 / Agent 仍是设计**。工作区内的二维漫游、
> 呼吸/眨眼/小跳、音乐泡泡、视频注视、闲置睡觉已经进了 `winmon_pet.py`；
> 主程序只传 `music / video / 无` 三个粗类别，不把曲名和系统控制塞进动画层。
> 动作包和 Agent 仍按下面的边界推进。

## 1. 三条边界

1. **Agent 只控制桌宠自己的表现**：说话、气泡、走动、看向、睡觉、吐泡泡。
   **不**通过桌宠去关窗口、结束进程、改系统设置；那些仍走 WinMon 原有的、
   有回读核对的控制路径。这样"人格怎么说"和"工具能做什么"不会混在一起。
2. **不隐藏人设**：用户选了 AI 人设，说什么、选哪个动作由模型理解决定；
   WinMon 只约束**动作词表**和预算，不替模型改写台词（除非用户自己写规则）。
3. **没有 key / 预算不足 / 不在允许时段** → 自动退回本地行为，
   不弹错误、不偷偷调用模型。

## 2. 三层结构

```text
本地状态层 PetBrain
  输入：是否在放媒体、媒体标题/状态、前台窗口、键鼠闲置、时间
  输出：idle / walk / watch / sleep / bubble / hop
        ↓（本地规则，0 token）
动作层 PetActionPlayer
  输入：动作名 + 时长 + 方向
  输出：精灵帧 / 窗口位置 / 小气泡
        ↑（有直连且用户允许时才走）
Agent 层 PetAgent
  输入：人设 + 当前事实 + 允许的动作词表
  输出：严格 JSON {say, action, duration, mood}
```

### 2.1 本地状态层（已实现基础版，不花钱）

- **音乐**：`media_playing` 为真且粗分类为 music 时，正面跟着节拍晃，
  每 1.8–3.6 秒吐一个泡泡 / 音符 / 爱心；切歌不打断大信息气泡。
- **视频/专注**：粗分类为 video 时，正面“认真看”，偶尔闪一下；持续很久
  且键鼠闲置才睡。
- **没人理**：系统键鼠闲置超过 150 秒且没有媒体，动作变慢、闭眼睡着；
  一动键鼠就醒。
- **动作**：21 段条带动作（待机/点击/工作/说话/日常/舞蹈），
  `perform("idle|walk|watch|sleep|bubble|hop|greet|spin|stretch|look|wake")`
  仍保留给旧调用；新菜单走 `perform_action(clip_id)`。右键「动作 ▸」和
  气泡「动作…」都调用同一套动作 id。
- **全屏漫游（已实现基础版）**：不再只沿任务栏横着走；在**工作区**内选二维目标点，
  横走用侧面（向左/向右各用一张镜像图）、向上用背面、向下用正面；
  碰到屏幕边/任务栏就停。拖拽仍然优先，拖到哪儿记哪儿。
- **窗口**：去掉 DWM 边框/阴影/圆角；用 GDI+ 32 位预乘 alpha +
  `UpdateLayeredWindow` 直接合成。没有颜色键/窗口区域/DWM 阴影，
  透明像素按 alpha 点击穿透，只有身体能点。

这些行为**不调用模型**，保证没有 key 的用户也能看到“活的”桌宠。

### 2.2 动作包（已实现：条带版）

早期草案是“每帧一张 PNG”；实际实现改成**每 10 帧一条横向条带**，
减少文件数并把运行时内存压到“当前一段”：

```text
desktop pet/actions/
├─ manifest.json
├─ idle/strip_00.png ... strip_09.png
├─ wave/strip_00.png ...
└─ ...
```

`manifest.json` 的关键字段：

```json
{
  "fps": 10, "height": 300, "per_strip": 10,
  "groups": [{"id": "待机", "label": "待机", "clips": ["idle", "look"]}],
  "clips": {
    "idle": {
      "label": "呼吸 / 待机", "group": "待机",
      "strips": ["idle/strip_00.png"], "frames": 100,
      "width": 268, "height": 300, "fps": 10,
      "per_strip": 10, "loop": true
    }
  }
}
```

规则：
- **只认本地文件**，启动/运行都不联网下载；`build_actions.py` 是构建工具，
  运行时不依赖 ffmpeg/Pillow。
- 条带按需解码：启动只读当前动作第 0 条，播到第 10 帧再读下一条；
  切换动作时释放上一段。
- 缺某段动作就回退到旧三视图精灵，不让桌宠消失。
- 素材条款见 `actions/LICENSE.txt` 与仓库根目录 `THIRD_PARTY_NOTICES.md`。
- 动作包只提供**画面**，`manifest.json` 不解析 Python、不执行代码。

### 2.3 Agent 层（人格由模型决定）

复用现有直连配置、预算账本和人设，不新建一套 key：

```text
系统提示：
  你是 <persona>。只输出一个 JSON：
  {"say": "不超过 50 字", "action": "idle|walk|watch|sleep|bubble|hop",
   "duration": 5, "mood": "..."}
  不能请求关窗/结束进程/运行命令；不知道就选 idle。
```

- 调用频率：默认 **2–5 分钟一次**，可在设置里关；受现有 `Budget` 限制。
- 只有用户显式开启「桌宠 Agent」且当前直连配置有效才调用。
- 返回非法 JSON / 动作不在词表 → 丢弃本次，保持本地状态（不惩罚、不重试狂刷）。
- 台词不经过 WinMon 的“改写”；只做长度/空值保护。用户接受“agent 的理解”，
  但**动作只能是桌宠动作**，这是安全边界。
- 桌宠的大信息气泡仍是只读事实；Agent 的小气泡是“它在说话”，两者分开，
  避免把模型的话伪装成系统读数。

## 3. 设置里多什么（当前实际）

- 桌宠：开关、大小、**活泼度（安静 / 标准 / 活泼）**、回到右下角；
  右键「桌宠设置…」是**独立面板**，主窗口在托盘里也能用，改完立即生效。
- 动作菜单：右键「动作 ▸」/ 气泡「动作…」打开 6 类 21 段，只影响桌宠表现；
  Agent 以后也走同一套 `perform_action(clip_id)`。
- 完整设置：主窗口隐藏/最小化时，设置窗不再 `transient(root)`，
  会独立显示（这是“桌宠没法脱离主界面响应设置”的修复）。
- Agent：开关、频率、最大每日调用、使用哪个人设、当前直连对象（复用）——
  **仍是设计，未实现**。
- 预算不足 / 没 key 时显示“本地模式”，不反复弹提示。
