## 零、WinMon 是什么，以及它**不做什么**

**它是"看见层"**：把 Windows 上同时开着的东西摊开给你看 —— 有哪些窗口/进程、
各自占多少内存和 CPU、哪个在放什么歌或视频、哪个开着却没人用。

**它只做系统允许的控制**（每一件都能核对）：

- 关窗口 / 结束进程（发系统消息、结束进程，然后**回读确认真的没了**）
- 保存与恢复窗口布局、最小化别的窗口
- **按系统媒体会话发播放/暂停/上一首/下一首**（发完重读状态，变了才说生效）
- 用 URL 协议或命令行打开程序

**它不做的**（这是明确的产品边界，不是"暂时没做"）：

- ❌ **不去模拟键盘/鼠标操作别的程序**。Windows 有意限制普通进程做这件事，
  实测三种注入方式全部"发得出去、没人响应"，继续做只会时灵时不灵。
- ❌ 不去点别的程序界面里的按钮、不猜坐标、不靠图像变化替你做点击。
- ❌ 不给"注入了但没法核对"的动作写"成功"（宁可说"没生效"）。

想要"抬眼就能看到正在放什么、后台谁在占资源"，用主界面的媒体那一行；
桌宠形态（点一下弹出信息面板）**规格已留档，尚未定稿**。

## 一、快速开始

**克隆下来之后，三步就能跑起来**（不需要安装、不写注册表、不装任何第三方包）：

```bat
git clone https://github.com/<你的用户名>/winmon.git
cd winmon
py winmon.py                          :: 直接开图形界面
```

**方式 1（推荐）**：双击项目里的 `启动WinMon.bat`

- 选择 `[1]` 打开图形界面
- 选择 `[2]` 运行环境自检（检查画面捕获与终止能力是否正常）

**方式 2**：想要桌面快捷方式（可选）——跑一次 `py tests\make_shortcut.py`，
它会用**这台机器**的 `pythonw.exe` 与 `winmon.py` 绝对路径生成一个
**`winmon1.0.lnk`**（用 `pythonw` 启动，**不会弹黑色控制台窗口**）；
`--remove` 可以删掉它。旧的「WinMon 程序监控」快捷方式会在生成时清理。

**方式 3**：命令行

```bat
py winmon.py                           :: 启动图形界面
py winmon.py --scan                    :: 不开界面，打印当前屏幕窗口清单
py winmon.py --scan --all              :: 连同屏幕上看不到的隐藏窗口一起列出
py winmon.py --json                    :: 以 JSON 输出窗口清单（便于脚本二次处理）
py winmon.py --catalog                 :: 列出系统里装了哪些可启动的程序（按类别分组）
py winmon.py --catalog --category 游戏娱乐  :: 只看某一类
py winmon.py --catalog --favorites     :: 只看收藏
py winmon.py --catalog --recent        :: 只看最近使用
py winmon.py --find 哔哩                :: 按关键词查找程序
py winmon.py --open 哔哩哔哩            :: 按关键词精准打开程序
py winmon.py --open 哔哩哔哩 --admin    :: 以管理员身份打开
py winmon.py --selftest                :: 运行环境自检（8 项，几十秒）
py winmon.py --clean                   :: 列出程序自己产生的可清理文件（只看不删）
py winmon.py --clean --yes             :: 清理缓存 / 日志 / 字节码 / 临时导出（不动你的设置）
py winmon.py --idle                    :: 列出"长期开着、没人用"的程序（只看，不关任何东西）
py winmon.py --idle --idle-minutes 5    :: 换个闲置阈值（分钟）
py winmon.py --version                 :: 打印版本（winmon1.0）
```

要求：Windows 10 / 11 + Python 3.9 或更高版本（自带 tkinter 即可，无需额外安装）。
如果程序启动失败，错误日志在**用户数据目录**里的 `winmon_error.log`
（默认 `%LOCALAPPDATA%\WinMon`，见[十一、文件说明](#十一文件说明)）。

### 换一台电脑 / 移植（需要准备什么）

WinMon 是**绿色程序**：没有安装过程、不装任何第三方包。
把整个文件夹拷过去就能跑，前提只有三条：

| 前提 | 说明 |
| --- | --- |
| **Windows 10 / 11** | 只用 Win32 API 与 UIA，不支持 Linux / macOS（`py winmon.py` 在非 Windows 上会直接退出） |
| **Python 3.9+**（用 [python.org 官方安装包](https://www.python.org/downloads/windows/)） | 官方安装包默认就带 tkinter；装完能用 `py -V` 看到版本即可。**不要**用不带 tkinter 的精简版/嵌入式版。开发与实测都在 **3.14.5** 上；3.9 / 3.10 没在真机上跑过，但代码刻意避开了 3.10+ 的语法与标准库（有 `from __future__ import annotations`、没有 `match`、没有结构化模式） |
| **tkinter 可用** | 验证：`py -c "import tkinter; tkinter.Tk()"` 不报错即可 |

**注册表只有一处**：你自己打开「开机自启动」时，会往
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 写一条 `WinMon`（不需要管理员权限），
关掉那个开关就把它删掉 —— 除此之外 WinMon 不碰注册表。

**运行时数据放在哪**：默认在 `%LOCALAPPDATA%\WinMon`（设置 / 缓存 / 操作历史日志 /
媒体快照 / 错误日志），**程序目录里只留源与文档**。想把数据跟着文件夹一起带走
（真正的"绿色便携"），设一个环境变量就行：

```bat
set WINMON_DATA_DIR=X:\WinMon\data
py winmon.py
```

换机器时那个目录里记的是**旧机器**的路径：缓存建议删掉
（`py winmon.py --clean --yes`，或直接删文件），偏好可以留着（认不出的条目会被忽略）。
旧版本如果曾把数据写在程序目录里，**启动时会自动搬到新位置**，不用手动处理。

**建议不要拷的**：`__pycache__/`（解释器会自动重建，跨机器拷贝没有意义）。

**权限**：日常使用**不需要管理员**。只有两种情况需要以管理员身份运行：
① 要结束以更高权限运行的程序；② 用 `--open X --admin` 提权启动程序（会弹 UAC）。
另外「结束关键系统进程」是被刻意拦住的，不因提权而放开。

**桌面快捷方式**（可选）：跑一次 `py tests\make_shortcut.py`，
它会把 `pythonw.exe` + 这台机器上 `winmon.py` 的绝对路径写成
`winmon1.0.lnk`（不弹黑框，图标与窗口共用 `winmon.ico`）。

**屏幕**：主界面**设计稿是 1160×730**（最小 1080×660），实际开窗时**按系统缩放自动放大**
（例如显示设置 150% → 开成 1740×1095），所以高 DPI 屏上文字不会挤在一起。
2026-10-19 起顶部动作收进左侧竖栏，**实时预览是主体**；窗口列表收成右侧紧凑侧栏，
窗口也比原来的 1280×800 更紧凑。默认字号 9，可在设置里调到 12。
屏幕比"设计稿"还小时界面会被裁掉 —— 这是唯一一个"换了设备要注意"的硬约束。

### 程序目录：读取系统里装了什么，并精准打开

切到「**程序目录**」标签页，即可看到系统里所有可启动的程序（本机 97 项），
支持**按类别分组浏览、收藏、最近使用**，以及搜索、双击 / Enter 打开、
以管理员身份打开、定位文件、导出 CSV。

- **多选**：按住 `Ctrl` / `Shift` 点程序行，底部会显示「已选 N 个」；
  「打开」「收藏」「设为类别…」都按整批处理，不会只动第一项。
- **单击只选中**：程序目录没有单独的预览区，所以单击的反馈是行变蓝 +
  底部计数；真正启动用双击或 Enter。
- **运行中的程序**用绿色文字标出（不再铺整行蓝底）。这样点击运行中的行
  也能看见选中高亮；「打开」走 `activate_window` 的还原 + 前台重试，
  不再只调一次 `SetForegroundWindow` 就被前台锁挡掉。

命令行也能用，适合脚本或建快捷方式：

```bat
python winmon.py --find 哔哩                        :: 查找
python winmon.py --open 哔哩哔哩                     :: 精准打开
python winmon.py --open "visual studio" --admin     :: 提权打开
python winmon.py --catalog --category 开发工具        :: 只看某一类
python winmon.py --catalog --favorites               :: 只看收藏（读界面里存的收藏）
```

数据来源（三个互补）：

| 来源 | 数量级 | 说明 |
| --- | --- | --- |
| 开始菜单 `.lnk` | ~95 项 | 记录了目标 exe、**启动参数**、工作目录，等价于"双击图标"，最精准 |
| 注册表 `Uninstall` | ~118 项 | 覆盖没有开始菜单项的程序（用 `DisplayIcon` / `InstallLocation` 反推主程序） |
| 当前运行中 | 动态 | 绿色软件 / 免安装程序也能被收录与管理 |

三个来源会互相重叠，所以目录构建的最后一步会**去重**（本机从 112 条降到 97 条）：
判据是"目标路径相同"或"软件名 + 安装位置相同"。去重只保留先出现的那条，
但会把重复项里的发行商 / 安装位置等信息补进保留项，不会丢信息。

#### 类别是自动分好的，也可以手动改

9 个类别：游戏娱乐 / 影音播放 / 浏览器 / 办公文档 / 开发工具 / 下载传输 /
安全防护 / 系统工具 / 其他。

自动归类靠两路信号：**软件名里的关键词**（"Steam"、"微信"）和**安装路径里的目录名**
（`X:\steam\...`、`C:\WINDOWS\system32\...`）。之所以不读注册表的类别字段，是因为
`Uninstall` 键里**没有**可靠的类别信息（`Publisher` 是发行商，不是类别）。

归类只是建议：选中某项后点「**设为类别…**」可手动指定，点「**自动分类**」恢复自动判断。
手动结果存在 `winmon_settings.json` 里，优先级高于自动判断。

#### 收藏与最近使用

- 「**☆ 收藏**」把常用程序标星；收藏项在列表里**排最前**并显示 ★
- 「**只看收藏**」「**只看最近使用**」两个开关可叠加，用来快速缩小范围
- 「**最近使用**」在你**成功**打开某个程序时自动记录（启动失败的不会记，
  免得列表里塞满点不开的条目），按最近一次使用倒序排列
- 最近使用最多保留 30 条，且会自动清掉 60 天以前的记录
- 收藏 / 最近使用 / 手动类别和界面设置一起写在 `winmon_settings.json`
  （`program_prefs` 字段），所以备份或清理只有一处

**精准启动的实现**：用 `ShellExecuteW`（普通启动用 `open` 动词、提权用 `runas` 动词），
与在资源管理器里双击图标的行为一致，因此会自动处理工作目录、启动参数、
文件关联，以及需要 UAC 提权的程序。

### 启动策略（实战总结，含两个容易踩的坑）

1. **已在运行的程序不重复启动**，而是切到前台。
   很多程序（浏览器、音乐播放器、视频客户端、Electron 应用）有**单实例机制**：再次启动时
   新进程会立刻把请求交接给已有实例并退出（退出码 0、什么也不做）。
   如果不判断，就会表现为"点了打开却没反应"。
2. **启动后确认进程真的出现了**；若 `ShellExecuteW` 报告成功但 2 秒内看不到对应进程，
   自动改用 `explorer.exe` 再启动一次作为兜底。
   这条兜底不是只为哔哩哔哩加的 —— 实测 `control.exe`（管理工具）、`TapTap` 等
   同样需要它才能被确认拉起，属于一类通病。
3. 提权（`--admin` / 以管理员身份打开）只走 `runas` 动词，不走 explorer 兜底
   （explorer 无法代为提权）。

实测耗时：已在运行的程序 ~0.01s 返回；新启动的程序约 0.2～2.5s（取决于是否需要兜底）。
不需要确认可就地关掉：`launch_item(item, verify=False)` 立即返回。

#### 解析 `.lnk` 时踩过的坑（已记录在代码注释里）

1. 本想用 COM 的 `IShellLinkW::GetPath` 直接解析（免依赖、更快），但**实测本机 Windows 11
   上 `GetPath` 对任何快捷方式都返回 `S_OK`，却把缓冲区写成指针垃圾值**；同一接口的
   `GetDescription` / `GetWorkingDirectory` 都正常。判断该 API 在现代 Windows 上不再返回
   可用字符串，因此改用 PowerShell 的 `WScript.Shell` 批量解析（95 个约 0.3 秒）。
2. **PowerShell 的编码是双重陷阱**：
   - 输入：Windows PowerShell 5.1 一律用**系统代码页**解码 stdin，中文路径会变成乱码
     → 改为写临时 UTF-8 文件 + `Get-Content -Encoding UTF8`；
   - 输出：管道重定向时 `[Console]::OutputEncoding` 默认仍是本地代码页，中文目标路径
     （如 `X:\Program Files\bilibili\哔哩哔哩.exe`）会被编成非 UTF-8，Python 侧解出来是乱码，
     导致 `os.path.exists` 判定失败、程序被误当成"目标不存在"而丢弃
     → 脚本开头强制把 `OutputEncoding` 与 `$OutputEncoding` 设为 UTF-8。
3. PowerShell 5.1 的 `ConvertTo-Json` 有时把字符串属性包成 `{value, Count}` 对象，
   Python 侧需要拆包。
4. Electron 应用在窗口标题还没设好时会短暂把 exe 完整路径当标题；
   `start "标题" exe` 参数用错也会产生同样结果。这类"标题其实是路径"的窗口
   会被识别并排除，否则目录里会混进一条名为
   `X:\Program Files\bilibili\哔哩哔哩.exe` 的假程序。

## 二、功能说明

### 1. 程序列表（左侧）

自动列出桌面上所有**正在运行、有可见窗口**的程序：

| 列 | 含义 |
| --- | --- |
| 程序 | 进程名（如 `chrome.exe`）。同名多窗口会折叠成一行，可展开 |
| 窗口标题 | 窗口标题栏文字，可据此辨认具体是哪个文档 / 网页 |
| PID | 进程 ID |
| 内存 | **两个口径一起给**：`工作集/私有提交`，例如 `229.0M/61.7M`（详见下面那段） |
| CPU | 该进程的 CPU 占用（整机百分比，与任务管理器同口径） |
| 状态 | 运行中 / 已最小化 / 无响应 / 后台隐藏 |

> **为什么这里的数字和任务管理器对不上？** 因为"内存"有好几个口径，而且
> 任务管理器把**同一个应用的多个进程合成一行**：
>
> | 名称 | 是什么 | 在任务管理器的哪里 |
> | --- | --- | --- |
> | 工作集（斜杠前） | 驻留内存，**含与别的程序共享的 DLL/共享页**，所以偏大 | 详细页的「工作集」列（要自己加出来） |
> | 私有提交（斜杠后） | 已提交的私有内存 | 详细页的**「提交大小」列** |
> | 私有工作集 | 工作集里不共享的那部分 | **主列表的「内存」列** |
>
> 实测同一刻的 Edge 主进程：工作集 238MB、私有提交 111MB、私有工作集 63MB；
> 而**同名 11 个 Edge 进程的私有工作集合计是 504MB** —— 任务管理器显示的就是后者。
> 想直接对上任务管理器：勾着「仅显示有窗口的程序」时，**收起的分组行**给出的就是
> **同名进程合计**（`229.0M/61.7M` 的合计），展开后是每个进程各自的数；
> 进程树那一页还专门有「私有(任务管理器)」一列。悬停任意一行会写明这行用的是哪个口径。

顶部工具：

- **搜索**：同时查“已运行窗口”和“程序目录”，按程序名 / exe / 窗口标题 / PID 过滤；
  输入中文名（网易云音乐）也能命中英文 exe（cloudmusic.exe）。结果浮层可点：
  运行中的在右侧窗口列表选中并预览；没运行的切到程序目录并高亮（不自动启动）
- **仅显示有窗口的程序**：取消勾选后改为每个窗口单独一行
- **显示隐藏窗口**：默认**不显示**屏幕上看不到的窗口。Windows 里不少程序（UWP 应用、输入法）
  会保留一些"cloaked"隐藏窗口，它们 `IsWindowVisible` 为真、也有尺寸，但用户屏幕上根本没有，
  若不过滤就会凭空多出一堆"幽灵程序"
- **显示无窗口进程**：勾选后也会列出后台进程（列出后同样可以结束）

#### 鼠标操作与键盘（单击选中 / 双击最小化）

| 操作 | 效果 |
| --- | --- |
| **单击** 某一行 | **只选中**（右侧出实时预览）—— 刻意**不碰任何窗口** |
| **双击** 某一行 | 该窗口**已最小化 → 还原并切到最前**；**否则 → 最小化它** |
| **Enter** 或 **中键** | 把选中的窗口**切到最前**（最小化的会先还原） |
| `M` / `Shift+M` | 选中的窗口逐个「最小化↔还原」/ 全部最小化 |
| **鼠标停在一行上** | 弹出说明：程序名 / 状态 / PID / 内存 / CPU，**以及它已经闲置了多久** |
| 双击预览画面 | 等同双击列表那一行（最小化/还原正在看的窗口） |
| 右键菜单 | 切到最前 / 最小化还原 / 批量最小化 / 批量还原 / 关闭 / 结束进程 / 闲置清理 … |

于是：**看一眼**（点一下选中，窗口不动）／**拿到面前**（Enter 或中键）／**收起来**（双击）——
三件事各有一个不打架的手势。按住 `Ctrl`/`Shift` 可以多选，批量最小化或还原。

**「活动」列的小标记**（因为行的颜色只能表达一种状态，而状态可以叠加）：

| 标记 | 含义 |
| --- | --- |
| `●` | 当前活动窗口（前台） |
| `▁` | 已最小化 |
| `顶` | 置顶窗口 |

三者可以同时出现（比如「最小化 + 置顶」就是 `▁顶`）—— 只靠行颜色做不到这件事。

三点说明：

- **单击为什么不切前台**：这工具的本职是"看着、不打扰"。以前单击就抢焦点，
  你只是想点一行看看它的画面，也会把正在干活的窗口赶到后面去。**规则变了，所以列表下面
  常驻了一行手势说明**，不用去猜。
- **双击为什么看"窗口自己是否最小化"**：原来的规则是"如果它已经在最前才最小化"，
  实测**只会唤醒、从来不会最小化** —— 一是"已在最前"这个信号靠 700ms 轮询维护、常年过期，
  二是**你人已经在 WinMon 里了，此刻双击哪一行它都不是前台窗口**，那条分支几乎永远走不到。
- **切到最前用的是"组合拳"而不是裸调 `SetForegroundWindow`**：后者受 Windows 前台锁定限制
  **会静默失败**（返回成功但窗口没动，用户看到的就是"点了没反应"）。现在会附加到**前台窗口
  所在线程**的输入队列、切换后**回读核对**、没成功还会重试，失败时状态栏如实说明。
  窗口操作都在后台线程执行，连续操作不会让界面卡顿。

### 关于"一个软件算成两个"的说明
UWP（应用商店应用，如「设置」）的窗口由**通用外壳进程** `ApplicationFrameHost.exe` 持有，
真正画界面的是另一个进程（如 `SystemSettings.exe`）。本程序会把外壳窗口识别出来，
在「程序」列显示成应用名并标注 **（应用外壳）**，避免同一个软件被重复计数。

**注意**：外壳窗口本身往往是隐藏的、抓取出来是黑屏，要预览「设置」请选
`SystemSettings.exe` 那一行，而不是 `ApplicationFrameHost.exe`。

### 2. 实时预览（主区域「实时预览」页）

启动后会自动选中当前前台窗口并显示画面；也可以在**右侧窗口列表**里点任意程序：

- **自动填满预览区**：抓取尺寸跟随面板大小，不再有 340×220～800×500 的
  「预览大小」选项（那个选项只改抓取分辨率，画面仍会被 Tk 二次缩放，
  选“小”反而可能被放大成一张巨图）
- **刷新速度**：1 / 2 / 5 / 10 / 15 / 30 FPS，按需调节（越低越省电）
- **自动省电**：切到别的标签页、窗口最小化或隐藏到托盘时**停止取帧**；
  WinMon 不是前台窗口时最多 **2 FPS**（画面右上角会写「后台省电」）；
  静止画面不会重复做 PNG 编码 / Tk 解码，但帧率统计照常。
  这是 2026-10-21 针对 `pythonw.exe` CPU 的优化：后台不再按 10 FPS 空转。
- **暂停刷新**：临时冻结画面
- **操作栏**：预览下方先选「请求关闭 / 强制结束」，再点「执行」。点箭头时
  两个操作**向上展开**，当前项整行蓝色填充，并各带一行说明：
  **请求关闭**是发关闭消息、程序可以先保存再退出；**强制结束**是直接终止、
  未保存内容会丢。强制结束仍会二次确认；请求关闭超时后，底栏会出现
  **「改为强制结束」**按钮；「强制结束整树」留在右键菜单与进程树页
- **预览跟随**：正在预览的窗口被关闭或结束后，不会停在最后一帧：
  清掉旧画面；「跟随选择」开着时自动切到下一个可见窗口，否则显示未选择状态
- **设置 → 使用说明 / F1**：刷新速度、媒体来源、视频联动手势、
  请求关闭与强制结束的区别统一放在设置里的使用说明中
- 面板右上角显示**实际帧率**
- **窗口被其他窗口挡住也能正常显示**（采用 `PrintWindow` 让窗口自己渲染）
- 窗口最小化时，显示的是它最小化之前的最后一帧；受保护/硬件加速窗口
  如实提示“画面为空”，不会留一块无解释的黑框

### 关于图标

列表里的程序图标取自 exe 本身的资源（`SHGetFileInfoW`），当前是 **28×28** ——
这是个"像任务管理器那样的列表"，目标是**小巧同时清楚**，所以四个候选都实测对比过：

这四个尺寸**都按真实显示像素目视对比过**（当时是 150% 缩放下渲染的，从上到下 16 / 24 / 28 / 32）。
结论：16 明显偏小、32 偏重，**28 是折中** —— 由原生 32 缩放而来，比 24 保留更多细节。
想自己复核（这两个工具会直接解码 exe 图标，绕开窗口）：

```bat
py tests\icon_realsize.py 16,24,28,32   :: 按真实显示像素对比
py tests\icon_montage.py 32 4           :: 放大 4 倍拼图，用来数像素细节
```

想改成别的尺寸不用改代码：

```bat
set WINMON_ICON_SIZE=32 && python winmon.py     :: 临时用 32
set WINMON_ICON_SIZE=16 && python winmon.py     :: 临时用 16
```

各尺寸的"空间代价"（行高 = 图标 + 6，列表区域约 645px 时一屏能看的行数）：

| 图标 | 行高 | 一屏约容 |
| --- | --- | --- |
| 16px | 22px | 29 行 |
| 24px | 30px | 21 行 |
| **28px（当前）** | **34px** | **18 行** |
| 32px | 38px | 16 行 |

两条**绑定的不变量**（都有测试守着）：

- **行高必须大于图标高度**，否则图标被裁成一条竖条（行高 = 图标 + 6）；
- **图标列宽必须 ≥ 图标尺寸**，否则图标显示不全。

（顺带一个容易误会的现象：用 `PrintWindow` 抓 WinMon 自己的界面时，图标列看着是空的 ——
那是 **Tk 画的图片抓不到**，不是没显示。）
想目视验证清晰度用 `py tests\icon_realsize.py 16,24,28,32`（绕开窗口直接解码图标）。

### 3.6 闲置程序（"长期开着、只耗电不使用"）

有些程序一开就是一整天，其实没人用 —— 白占内存、白耗电。勾上列表下面的
**「闲置超时提醒」**（**默认关闭**），WinMon 就会盯着这件事。

| 判定依据（任一成立就重新计时） | 说明 |
| --- | --- |
| 它的窗口是**前台窗口** | 你正在用它 |
| 它的 **CPU 占用**高于 1% | 它在算东西（后台编译、索引也算"在用"） |
| ~~它在放声音~~ | **2026-10-13 已删**：那条依赖的音频会话枚举在本机恒为 0，现在只看"窗口不在前台"与"CPU 几乎为 0" |

三个都不成立，才开始累计"闲置时长"。时长可选 **30 分钟 / 1 小时 / 2 小时 / 4 小时**（默认 30 分钟）。

到点之后：

- **默认「只提醒」**：状态栏提示 + 弹出**「闲置程序」清单**，逐项勾选（默认全勾）后点
  「关闭选中的」；点「稍后再说」则把这些程序的计时清零，重新开始算、到点再提醒。
- **提醒间隔**（默认 1 小时）：提醒过一次之后，这段时间内**不再自动弹窗**，
  只在状态栏提示"有几个闲置了，点清单查看"。可选 30 分钟 / 1 小时 / 2 小时 / 4 小时 /
  **「每天只提醒一次」** / 「本次运行只提醒一次」。
  **手动点「闲置清单」按钮不受限制** —— 你主动要看就该给你看。
  为什么要这个：多个程序会在不同时刻陆续越过阈值，不节流的话你刚关掉一个清单、
  过几分钟又被另一个弹一次。
- 「每天只提醒一次」看的是**自然日**，不是"满 24 小时"：今天弹过就不再弹，
  过了零点（日期翻篇）之后再有程序越线就再提醒一次。
  档位换回"几小时"时立刻按新档位生效（不会被当天已经提醒过这件事挡住）。
- 清单里还有一个 **「以后到点自动关闭（不再询问）」** 开关（**默认关闭**）。打开后到点直接关
  （这条**不受提醒间隔限制** —— "到点就办"和"要不要打扰你"是两件事）。

**安全约定（这一块最要紧）：**

- **只"优雅关闭"** —— 发 `WM_CLOSE`，等同于点窗口的关闭按钮。程序里有未保存的内容时，
  **它自己会弹"要不要保存"**，决定权回到你手里。
- **绝不强杀**：它没退出（多半正等你回答）就如实报告，WinMon 不会替你结束进程。
- **关键系统进程、资源管理器、任务栏、开始菜单、输入法、以及 WinMon 自己
  根本不会出现在清单里**（在采样阶段就过滤掉了）。
- **只管有可见窗口的程序**。托盘/服务这类没有窗口的后台进程不参与 ——
  它们"本来就不显眼但可能很有用"（同步盘、输入法、驱动面板），随便关掉风险太高。
- 关掉的每个程序都会记进**操作历史**，可以导出核对。

命令行可以只看不动手地检查一遍：

```bat
python winmon.py --idle                    :: 按默认 30 分钟判定，列出"此刻没在用"的程序
python winmon.py --idle --idle-minutes 5   :: 换个阈值（调试用）
```

### 3.7 工作区快照（右侧「工作区」页）

把当前一组窗口的**位置与最小化状态**按名字存下来，之后无论桌面乱成什么样，
选中它点「应用」就回到那个样子。典型用法是"写代码 / 看视频 / 打游戏"各存一套。

| 按钮 | 做什么 |
| --- | --- |
| **保存当前布局…** | 给现在这套布局起个名字存下来（同名会覆盖） |
| **应用**（或双击列表） | 把选中的工作区套回当前窗口上 |
| **用当前布局更新** | 你微调过布局后，用它覆盖已有的那个工作区 |
| **删除** | 删掉这份快照（**只删快照，不会动任何窗口**，删前会问你） |
| **刷新列表** | 重新读一遍 |

还有一个 **「应用时顺带最小化其它窗口」**（默认关闭）：勾上之后，应用工作区时会顺手
把**不在这个工作区里**的窗口收起来 —— 相当于"一键收拾桌面"。保护进程与 WinMon 自己不动。

**三条设计上的取舍（都写在界面上，免得你以为它坏了）：**

- **恢复只对当前开着的窗口生效，不会替你启动程序。** 某个程序这次没开，它会列在
  "没开：xxx" 里告诉你，而不是偷偷帮你打开（那是另一件事，而且很危险）。
- **匹配靠"可执行文件名 + 窗口标题"，不保存窗口句柄** —— 句柄下次运行必然不同。
  标题变了（浏览器那种）就退回按可执行文件名配；同一个程序开多个窗口时按顺序一一对应，
  不会把同一个窗口分配两次。
- **位置会夹回屏幕内。** 快照可能是插着外接显示器时存的，拔掉之后那些坐标就在屏幕外了 ——
  不夹的话窗口会被挪到看不见的地方，你会以为"东西丢了"。

工作区存在 `winmon_settings.json` 里（和别的设置同一个文件），最多 20 套、每套最多 60 个窗口。

### 4. 终止程序

选中程序后，可用以下任一方式：

| 操作 | 说明 | 什么时候用 |
| --- | --- | --- |
| **请求关闭** | 发送关闭消息，等同于点窗口右上角的 × | 首选。程序会正常保存数据后退出 |
| **强制结束** | 直接终止该进程 | 「请求关闭」超时/无效（卡死 / 无响应）时用 |
| **强制结束整树** | 直接终止该进程**及其全部子进程** | 程序带一堆子进程（如浏览器、IDE）时用 |

其他入口：

- **双击列表项**：把该程序窗口切到前台
- **右键列表项**：完整菜单（显示画面 / 加入总览 / 切到前台 / 关闭 / 结束进程 / 结束进程树 / 打开文件所在位置 / 复制 PID、标题、路径）
- **Delete 键**：结束当前选中的进程
- **结束进程**会弹出确认框，明确显示程序名、PID、窗口标题，避免误杀

### 5. 安全保护

程序内置了两道保护：

- **关键系统进程黑名单**（`csrss.exe`、`winlogon.exe`、`lsass.exe`、`services.exe`、`svchost.exe`、`dwm.exe` 等）
  尝试结束它们会被**直接拒绝**并说明原因，因为结束这些进程会导致系统蓝屏或桌面崩溃。
- **高风险进程二次提示**（`explorer.exe`、输入法/开始菜单相关进程）
  会额外提示后果（例如任务栏和开始菜单会短暂消失），由你确认。
- **禁止结束 WinMon 自己**。

### 6. 权限说明（重要）

如果目标程序是**以管理员权限运行**的（例如以管理员身份启动的安装程序），
普通权限的 WinMon **无法结束它**，界面会提示：

> 该进程权限高于本程序，若无法结束请以管理员身份重新运行 WinMon。

此时**右键 `启动WinMon.bat` → 以管理员身份运行**，再重试即可。

## 三、工作原理

```
枚举窗口 ──► PrintWindow(PW_RENDERFULLCONTENT) 让窗口自绘完整内容
          ──► GDI StretchBlt 直接缩放到目标尺寸（全程在 C 层完成）
          ──► 取出 24 位 DIB 裸像素
          ──► 后台线程 → 主线程：抽样 + 生成十六进制像素串 → PhotoImage 上屏
```

几个关键取舍（都经过本机实测对比）：

| 方案 | 实测结果 | 结论 |
| --- | --- | --- |
| DWM 缩略图 `DwmRegisterThumbnail` | 调用返回成功，但画面**不渲染**（全黑） | 未采用 |
| `PrintWindow` + 全尺寸生成像素 | 760×480 时约 180 ms/帧（约 5 FPS） | 太慢 |
| `PrintWindow` + **半尺寸抽样 + `zoom(2)`** | 640×400 时约 11 ms/帧（约 90 FPS） | **采用** |

其他实现要点：

- **后台捕获线程**：所有抓屏在独立守护线程中进行，界面不会卡顿；每个窗口缓存自己的 GDI 对象，避免每帧重复创建。
- **句柄归一化**：64 位下 GDI 句柄的高 32 位是符号扩展的（形如 `0xFFFFFFFFA901105F`），直接传给 `wintypes.HDC` 会抛 `OverflowError`，因此统一按 32 位无符号掩码处理。
- **单帧失败不影响整体**：某个窗口抓取失败只影响它自己，不会中断其它程序的预览。

## 四、常见问题

**Q：为什么列表里少了一些程序？**
A：默认只显示**屏幕上看得到**的窗口。Windows 里 UWP 应用和输入法（如 `TextInputHost.exe`）
会保留隐藏的"cloaked"窗口，它们占据了窗口列表却看不见。勾选顶部「显示隐藏窗口」即可把它们也列出来，
此时状态列会标注「后台隐藏」。

**Q：为什么某个程序显示的画面是黑的？**
A：少数特殊窗口无法被捕获，典型是**隐藏窗口**（如 `ApplicationFrameHost.exe` 外壳窗口、
输入法宿主 `TextInputHost.exe`）和部分受保护的视频播放窗口（DRM 内容）。
这类窗口本身没有可抓取的常规绘制内容，属于 Windows 的限制。

**Q：为什么画面有点糊 / 有锯齿？**
A：为了「实时」，画面按 1/2 分辨率抓取后再由 Tk 放大 2 倍显示，这是本程序能做到高帧率的关键。若要看清晰画面，把「画面」尺寸选大一些（如 800×500）会更接近原始分辨率。

**Q：预览窗口比自己窗口小的时候会怎样？**
A：画面会自动等比缩小以完整显示（用 Tk 的 `subsample`）；比面板小时会居中放大显示。

**Q：会占用很多资源吗？**
A：只在**选中预览**和**打开实时总览**时才抓屏，并且按你设定的刷新率节流；切到别的标签页或暂停后会停止取帧。空闲时不抓屏。

**Q：`--selftest` 做了什么？**
A：无界面全链路自检，共 **8 项**：窗口枚举 → 画面捕获 → 画面渲染 → 图标提取 → 进程终止
（会临时启动一个 `sleep` 进程来验证终止能力，不会碰你任何真实程序），
最后 3 项是**出货守门员**：随附文件在不在（`media_session.ps1` / `winmon.ico`）、
开机自启动命令指向的脚本是否真实存在、桥接脚本是不是 v2（原子写快照）。

## 五、附加脚本与模块

| 文件 | 用途 |
| --- | --- |
| `winmon_core.py` | **核心层**：窗口/进程采集、画面捕获、进程结束、图标提取、操作记录。不依赖 tkinter，可当库用 |
| `winmon.py` | 图形界面 + 命令行（`--scan` / `--json` / `--selftest` / `--smoke`） |
| `scan_windows.py` | 命令行扫描窗口清单（等价于 `winmon.py --scan`） |
| `close_others.py` | 批量关闭除"当前窗口"以外的所有窗口 |

核心层可以单独使用：

```python
import winmon_core as core

wins = core.collect_desktop()                 # 当前屏幕上所有可见窗口
print(core.get_system_summary())              # 概览：几个窗口、几个软件

cap = core.WindowCapturer()                   # 抓某个窗口的画面
raw, w, h = cap.grab_window(hwnd, 1920, 1080, 480, 300)
cap.release()

core.terminate_process(pid)                   # 强制结束
core.graceful_close_window(hwnd)              # 优雅关闭
print(core.IconCache(32).get(wins[0]))        # 程序图标（base64 PNG）
```

### close_others.py —— 一键关闭其他所有窗口

```bat
python close_others.py --dry-run     :: 先预览：列出将要关闭哪些窗口，不执行
python close_others.py               :: 优雅关闭（发送关闭消息，等同点窗口 ×）
python close_others.py --force       :: 优雅关闭超时后强制结束
python close_others.py --self-path "X:\xxx\yyy.exe"   :: 指定要保留的"当前窗口"
python close_others.py --keep 1234   :: 额外保留某个 PID
```

安全设计（很重要）：

- **按可执行文件路径保留**，而不是按 PID。PID 会变化，路径不会，因此不会误关"当前程序"
- 未指定 `--self-path` 时自动取**前台窗口**所属进程作为"当前窗口"
- 只处理屏幕上**真实可见**的窗口；隐藏窗口和 UWP 外壳窗口不碰
- 自动跳过系统关键进程（`csrss.exe`、`winlogon.exe` 等）
- 支持 `--dry-run` 先确认名单；结束后把操作记录写入临时文件

## 六、操作历史（独立窗口 + 独立日志）

所有**有副作用**的动作都会留痕：关闭窗口、结束进程/进程树、关闭视频、
媒体命令（切歌/播放暂停）、唤醒媒体应用、恢复工作区、设置变更、清理文件。

**两处都能看到**：

- **独立窗口**：工具条点「操作历史…」。可以按动作筛选、按关键词搜索、复制全部、
  导出成 txt、在资源管理器里定位日志文件。表格列是
  `时间 / 程序打开时间 / 动作 / 对象（程序 + 窗口）/ 结果 / 备注` ——
  **时间只到分钟**（按定稿口径），"程序打开时间"是该进程的启动时刻，和"什么时候关了它"配成一对。
- **独立日志文件**：`<数据目录>\winmon_history.log`，一行一条、只追加，
  **关掉 WinMon 再打开记录还在**；超过 2MB 会自动轮转成 `.log.1`。
  制表符分隔，直接用记事本打开就能看（不会挤成一团）。

记录长这样（真跑出来的样例）：

```
2026-10-12 17:39	恢复工作区	工作区「验收工作区」	还原：python.exe｜WinMon-WS-Beta · python.exe｜WinMon-WS-Alpha
2026-10-12 19:05	媒体命令	当前播放器	播放/暂停：应用接受了「pause」命令
```

**两个「清空」不一样，别点错**：

| 按钮 | 作用 |
| --- | --- |
| **清空列表** | 只清掉窗口里显示的列表，**日志文件不动** |
| **清空日志文件…** | 真的删掉磁盘上的留痕（会先问一次，无法撤销） |

**日志留多久**：设置里可选 **7 / 30 / 90 天（默认 30 天）**，
到点会在启动时自动清理（删之前留一份 `.bak`，删错了还能找回来）。

## 七、视频联动：只保留「监视当前窗口 / 停止监视 / 直接关闭视频」

> **2026-10-12 起砍掉了"自动打开视频"这条线。** 之前想做到"看画面变化就知道在放视频、
> 然后自动把视频点开"，试下来（HANDOFF §9.7）发现：客户端里的卡片只认真实指针输入，
> 我们点不动；靠图像变化去猜并替代点击，误判成本又太高。于是这一整条需求被放弃，
> 相关代码（决策表、来源打分、视频卡片读取、`--videos` 命令行、来源/卡片弹窗）
> 连同它们的用例一起删掉了。

现在工具条上「视频联动」就三个按钮，加媒体控件排在同一行：

| 按钮 | 作用 |
| --- | --- |
| **监视当前窗口** | 在左侧列表里选中一个窗口（客户端 / 浏览器 / 本地播放器都行），WinMon 采一段画面判断它**是不是在放视频**。判不出来会如实说"不像视频"，不会假装成功 |
| **停止监视** | 结束这次监视（不再周期性地检测播放） |
| **直接关闭视频** | 立刻按「关闭方式」处理当前监视/选中的那个视频窗口（不弹询问框） |

监视到"正在播放"时会**弹一次询问**（问你要不要关掉），按 **Space** 确认、**Esc** 继续播放；
按钮文字会写清点下去到底会发生什么（关窗口 / 关标签页 / 暂停 / 返回上一页）。

**关闭方式**在工具栏第二行原来的位置已随视频区一起简化，现在只有"监视/停止/关闭"三个动作，
关闭方式仍按你上次选的那个（默认"关闭当前窗口"，不依赖前台、不注入键盘）。

### 看「正在播放」+ 媒体应用（可在工具栏一行里直接操作）

媒体相关的控件现在都在**工具栏那一行**（原来在窗口底部，现在底部只留状态）：

```
视频联动：监视当前窗口 停止监视 直接关闭视频
媒体：<曲名·状态>　播放器：[媒体应用▾] ☑自动启动 ◀◀ ▶/⏸ ▶▶
```

- **曲名/状态是真读出来的**，不是猜的：WinMon 读 Windows 的**系统媒体会话**
  —— 网易云、QQ音乐、Spotify、以及**浏览器里的网页播放器**都会发布到这里，
  所以网页端也看得到。每 4 秒问一次系统（后台线程，不卡界面）。
  **不再显示播放进度**（这是一项**明确放弃**的需求，见 HANDOFF §9.7 的边界说明）。
- **「媒体应用」只把命令发给「你选的那个」**。下拉框里的清单来自**三个来源**，
  顺序也是这个优先级（2026-10-16 改）：
  1. **此刻真的有媒体会话的应用** —— 这是**第一真源**：任何程序只要向系统发布了
     媒体会话（新出的播放器、UWP 应用、绿色版、浏览器里的网页播放器……），
     都会**自动**出现在清单里并能被精确控制。认不出名字的会标成「（媒体会话）」，
     **不会**假装成播放器；
  2. 你机器上**开始菜单里真装的**音乐 / 浏览器类程序（条目带「（菜单）」）——
     此刻没在放东西也能选、也能唤醒；
  3. 一小张**常见播放器**表（网易云 / QQ音乐 / 酷狗 / 酷我 / Spotify / foobar2000 /
     PotPlayer / VLC / Edge / Chrome / Firefox）—— 它现在的职责只有两条：
     把会话里的家族名换成看得懂的名字、以及"没在放时也能唤醒"。
     **它不再是准入门槛**。
  带「（运行中）」标记的能用进程名精确匹配媒体会话。
- **「媒体应用▾」是多选面板**：点一下只出现这一个面板（不会再叠出原生单选下拉；
  键盘 Down / F4 / 空格也能打开），勾选多个后按「确定」。
- **覆盖面不再取决于"你这台机器装了什么"**：以前下拉框只列写死的候选表 ＋
  开始菜单里媒体/浏览器两类的条目，换一台机器、或用户装了个表里没有的播放器，
  就**选不到也控不了**。现在以系统媒体会话为准 —— 谁能发布会话，谁就认得出来。
- **家族名 / UWP 应用也认得**：Edge 在会话里报的是家族名 `MSEdge`、
  UWP 应用报的是 `包名_哈希!App`，都不是进程名。以前用"进程名相等"去判断
  "它在不在跑"，会把这**正在放歌**的应用判成"没在运行"（于是你点「播放/暂停」，
  WinMon 却在问要不要替你启动它）。现在按**主干**匹配，而且"此刻有会话"本身
  就当作"在运行"。
- **切歌/播放暂停走系统媒体会话命令**：上一首/下一首会对每个会话试命令并**回读核对**
  状态有没有真的变，变了才说生效；播放/暂停按应用发 `TryPlay/TryPause`，下一个
  4 秒刷新会反映真实状态。会话拒绝命令时也会退回键盘媒体键并**如实说明**这一路
  无法核对（实测键盘媒体键在有些机器上"发得出去但没人理"）。
- **三个媒体键按播放器的通用顺序排列：`◀◀ 上一首`、`▶/⏸ 播放暂停`、`▶▶ 下一首`**
  （2026-10-21 调整）。中间键按当前状态显示：暂停时是 `▶`，播放时是 `⏸`；
  只控制媒体，不调音量、不读进度、不关闭程序。
- **「◀◀」「▶/⏸」「▶▶」是一条路走到底**（2026-10-12 合并，原来"唤醒"和"媒体键"
  是两排重复的按钮）：
  1. 选中的应用没在跑 → 勾了「自动启动」就**先替你启动它**（没勾就如实说不启动）；
  2. 把命令**按应用**发过去（只给你选的那个，不动别的播放器；多选时逐个匹配）；
  3. 它**没有媒体会话**（网易云就是：进程在跑但不发布会话），或者会话**拒绝了
     这条命令**（浏览器也可能）→ **自动改用系统媒体键**（"谁活跃发给谁"），
     而不是只报一句失败。
  状态栏会说明这一步实际用了哪一种，所以不用你猜。
- **网页端（Edge/Chrome 里的音乐网站）**走系统媒体会话，曲名/歌手是原样的中文
  （曾有一个 bug 把中文解成乱码 —— 原因是 PowerShell 桥接脚本的**管道输出是
  GBK 而不是 UTF-8**，已修，见 HANDOFF §9.12）。
- **网易云这类"不向 Windows 发布会话"的客户端**：Windows 的系统媒体会话里根本没有它，
  但它的**窗口标题就是歌名** —— 这时 WinMon 会读标题栏，主界面只显示
  `网易云音乐：歌名 - 歌手`；来源说明（“从窗口标题读的，可能带额外文字”）
  移进「设置 → 使用说明」，不再挤占那一行。
  浏览器**不会**走这条（它的标题里混着标签页名，拿它当歌名就是编造）。
- 那一行还会**冠上正在播放的程序名**（会话里报的是家族名 `MSEdge`，
  WinMon 会显示成 "Microsoft Edge"）；没有程序在放时写「（<你选的应用> 没有在播放的媒体）」。
- **什么都没做成时不写操作历史**（没在跑又没勾自动唤醒、或者三步都失败）：
  只在状态栏说一句，免得日志被"其实什么也没发生"的记录塞满。

## AI 工作伴侣（阶段 1.5–8.14）

WinMon 的 AI 接入层：**本地识别 + 本地事件 + 用量预算 + 可选直连 + 本地 HTTP / 剪贴板桥 + 跟随式助手**。
默认**不联网、不调模型、不花 token**；只有显式开启「直连」才会产生外部调用。

### 识别与本地事件（0 token）

1. **识别你正在用哪个 AI**（桌面客户端 / 网页标签），给出置信度与判据；
2. **把本地能确定的异常变成事件**（无响应窗口、系统盘告急、MCP 工具失败），
   用托盘气泡提醒；AI 按需来读，不读就永远是 0 token。

**主界面常驻一张 AI 状态卡**（2026-10-19 用户要求）：不再是一整行灰字，而是
左侧深色 `AI` 标签 + **加粗的识别对象** + 带底色的接入状态 + 一行小字用量。
状态只写接入方式和路径：`已接入 · MCP（客户端）` / `已接入 · API（模型）` /
`未接入 · 纯本地`，一眼能分清“识别到谁”和“到底有没有接上”。
**状态是文字，不是按键**；旧版的「复制现场」按钮已删除（2026-10-21 用户要求），
点它不会再发生任何事，也不会再出现。
**不再统计 AI 的运行时长 / 前台计时 / 激活次数** —— 主界面只看“现在是谁在前台”，
不保存历史。用量仍按 `真实 X · 精确 Y · 估算 Z token` 三栏。
打开「设置 → AI 用量」看到的是一张仪表盘：今日已用进度、真实 / 精确 / 估算三栏、
当前识别到的 AI、直连状态和最近 5 条记录，不再是整块等宽文本。
这样"这个数字是谁的"不用再猜：直连调用记在 `WinMon direct`，MCP 调用记在
客户端名（如 `Claude Desktop`）下。媒体那一行同样改成高亮卡片：`媒体` 标签 +
加粗的“应用：曲名 · 状态”，来源说明移进「设置 → 使用说明」。

### 三种使用定位（默认：本地，0 token）

| 模式 | 会自动调用模型？ | 适合 |
| --- | --- | --- |
| **只读** | 否 | 写程序/写项目：WinMon 只看窗口、记录事件；不提醒、不自动调用；AI 通过 MCP 或你复制的现场来读 |
| **本地**（默认） | 否 | 日常：WinMon 把当前时段和角色说明交给**你接入的 AI**，由它决定要不要提醒；token 始终 0 |
| **主动 AI** | 是（必须你显式选） | 想让 WinMon 自己直连当前 AI 做值守/解释时 |

助手窗口顶部会直接写出**接入状态**，不用你自己核对：

- `已接入 · MCP（Claude Desktop）`：客户端确实在调 WinMon 工具（15 分钟内）；
- `已接入 · API（glm-5.3）`：当前 AI 的直连配置可用；只有「主动 AI」模式会调用；
- `未接入 · 纯本地`：没有 MCP、也没有可用 API；不联网、不调模型，
  主界面不会出现「复制现场」按钮；
- 主界面左侧的「AI 工作区…」打开 AI 页，页内有「打开接入…」：
  默认只展示 **MCP 一条推荐路径**；直连 API key、工作区、人设、主动搭子
  都收在「高级 / 更多设置」里，不配 key 就是纯本地；
  顶部状态条直接用绿色/琥珀色说明“接上了没有”。

### 休息提醒：由接入的 AI 说，WinMon 不弹窗

用户 2026-10-19 的纠正：提醒要**建立在接入 AI 之后**，由 AI 读角色说明自己说，
不是 WinMon 按时间弹窗。现在：

- WinMon **没有**时间提醒弹窗，也**没有**“连续工作 50 分钟”的计时；
- 它只产出 `companion` 素材包：
  - `facts`：当前时间/时段、前台应用类型、**媒体应用名**、**游戏应用名**、
    浏览器**网页标题**、空闲/本次分钟；
  - `persona`：用户选的人设（默认关心型）；
  - `fallback`：只给没有模型的路径用的兜底句；
  - `once_key`：同一个时段每天一次；
- MCP 的 `initialize.instructions` 就是 AI 的**角色记忆**：
  “每次对话开始调用一次 `winmon_ai_sessions`；`companion.facts` 是事实，
  `companion.persona` 是人设，`fallback` 只是兜底；措辞自己定，不要逐字复制；
  只有 `speak=true` 才说；用户写代码/做项目时不要主动打断”；
- 网页 AI / 没接 MCP 的客户端：剪贴板交接提示词里带同一份事实、人设、兜底与工作区建议，
  粘过去后 AI 仍会按这个人设自由发挥；
- 时段仍是 24 小时制（不是使用时长）：

  - `22:00–05:59` 深夜：`现在 01:54，深夜了；该休息了，别熬太晚。`
  - `06:00–08:59` 早上：`现在 07:30，早上好；先喝口水、吃早饭，再开始今天的活。`
  - `11:00–13:59` 中午：`现在 12:10，中午了；起来吃饭、午休一下。`
  - `17:00–19:59` 傍晚：`现在 18:20，傍晚了；收个尾，准备吃饭/下班。`
  - 其它时间没有提醒数据（`reminder` 为空）；上面四句只是 `fallback`，
    AI 可以换成自己的说法。

- **人设**：AI 工作区 → 打开接入… → 更多设置 → 人设，默认关心型，
  可切损友型/安静型；
  「复制人设」会把一段可粘贴到 AI 自定义指令的人设卡复制走。
  人设卡只写五件事：**身份/语气、可以提什么、绝不提什么、什么时候闭嘴、一次说多少**。例如：

  ```text
  你是用户的桌面搭子，语气像熟人，不油腻。
  可以提：时间、写代码/写文档、正在放的音乐应用、游戏应用名、浏览器标题。
  不要提：曲名/歌手、健康、外貌、收入、感情、政治。
  写代码/开会/共享屏幕/深夜时不要调侃；不确定就沉默。
  一次最多一句，不重复上一句。
  ```
- **自定义人设库**：人设下拉里除了关心 / 损友 / 安静，还会列出**已保存的人设名称**
  和「更多…」。
  - 「导入人设…」支持 `.txt` / `.md` / `.json`（UTF-8，≤4000 字）；
  - GitHub 社区常见的角色卡会读取 `data.name`、`description`、`personality`、
    `scenario`、`system_prompt` 等字段；Markdown 会读 YAML front matter 和一级标题；
  - 导入后自动用角色卡名字命名，可在「更多…」里**重命名、保存、使用、删除**；
  - 导入后「复制人设」会带上你的全文和名字；安全边界（不评价健康/收入/感情、
    专注/会议/夜深不调侃）仍然生效，自定义只改语气。
- **主动搭子（C，默认关）**：接入窗口第 5 节，必须用户手动打开。
  默认连「专注/会议/夜深」也不允许，三个开关逐项打开；每天最多 3 句、
  最短 30 分钟；只在「主动 AI」+ 当前 AI 有 key + 预算可用时才会直连。
  没有本地兜底、不后台偷跑；不开启就完全不会主动调用。
- **手动「搭子说一句」**（B）：助手窗口按钮或 `--ai-quip`。
  `active` + 当前 AI 有 key 时直连一次（会花 token，账本可见）；
  否则按人设/检测到的应用名本地兜底（0 token）。
- **工作快照**：读前台窗口 + 旁边窗口，本地判断“编程/文档/查资料/游戏”，
  显示当前在做什么；「本次会话 X 分钟」只做显示，**不用于提醒**；不调用模型。
- 「交给 AI」把这份现场（含事实/人设）交给你的 AI；只有模式选「主动 AI」
  且当前 AI 有 key 时才会直连，并显示 `本次 N 次 / N token`，不存在“偷耗”。

```bat
py winmon.py --ai-sessions      :: 主 AI + 候选 + 判据（--json 机器可读）
py winmon.py --incidents        :: 本地事件（--json 同理）
py winmon.py --ai-usage         :: 当前识别 + 真实/精确/估算三栏用量
py winmon.py --ai-chat          :: 助手本地记录（直连回答 / 交接 / 手动保存的回复）
py winmon.py --ai-context       :: 生成给网页 AI 的上下文包
py winmon.py --ai-context --copy :: 同上，并复制到剪贴板（剪贴板桥）
py winmon.py --ai-assist "现在最值得注意什么"  :: 跟随当前 AI：能直连就调用，否则生成交接文本
py winmon.py --ai-quip         :: 让搭子按人设说一句（本地兜底，0 token）
```

判据（与 MCP.md §10.3 一致）：
**用户 pin > MCP 连接级实锤 > 当前前台窗口 > 识别置信度 > 资源占比**。
**不统计运行时长/前台累计/激活次数**（2026-10-21 已删除）；“当前在前台”
是当场 0/1 状态。资源占比只用于并列时打破平局，**网页端不可归因，恒为 0**。
用环境变量 `WINMON_AI_PIN=Claude` 可指定主 AI。

### MCP 接入（桌面 stdio / 本地 HTTP）

```bat
py winmon.py --mcp-selftest     :: 协议与工具自检（不需要客户端）
py winmon.py --mcp-stdio        :: stdio 服务器（Claude Desktop / Cursor）
py winmon.py --mcp-http         :: 本地 HTTP（默认 8765，只绑 127.0.0.1）
```

```json
{"mcpServers":{"winmon":{"command":"python","args":["D:\\winmon\\winmon.py","--mcp-stdio"]}}}
```

工具：`winmon_ai_sessions`、`winmon_incidents`、`winmon_playbooks`、
`winmon_budget_status`。`winmon_ai_sessions` 额外返回 `companion`
（当前时段、该不该由 AI 转达的提醒、`once_key`、角色说明、工作区建议）。
HTTP 模式必须带 `Authorization: Bearer <token>`
（token 在启动时打印到 **stderr**，只显示一次）；有 `Origin` 头时还要在白名单里。
**网页端要实时调用**，需要用 cloudflared / ngrok 之类的隧道把 `127.0.0.1:8765`
暴露成 HTTPS —— WinMon **不捆绑隧道**；不 tunnel 就用上面的剪贴板桥。

### 用量：真实 / 精确 / 估算三栏（默认 1000 万 token/日）

- **真实**：直连 API 响应里的 `usage`（`token_source=provider`），这是唯一能当账单看的数；
- **精确**：MCP 工具结果用目标模型的分词器数出来（`token_source=tokenizer`）；
  需要在 `winmon_ai_provider.json` 里设 `"exact_tokens": true`（默认关）——
  开启后 MCP 进程会把**工具结果**发给智谱 `/tokenizer` 计数，不发送截图或路径；
- **估算**：既没有直连、也没有开精确分词时的本地兜底（`token_source=estimated`）。

> **为什么 MCP 没有"客户端账单"**：MCP 协议只传工具参数与结果，不传客户端整段对话的
> `usage`；客户端花了多少 token 在它自己那边。WinMon 能精确统计的只有
> "我交给它多少上下文"和"我自己直连花了多少"。把估算说成客户端账单是不诚实的，
> 所以界面一律分栏标注，且直连/精确优先。

- 80% 软提醒；100% 停止直连、MCP 降载（只回预算状态，不返回数据）；
- **恢复只能在本机**：主界面 →「设置 → AI 用量」，或 `--ai-usage` 查看；
  托盘右键的「设置…」也打开同一个窗口。**MCP 没有任何修改预算的工具**
  （防止提示注入自己解锁）。

### 可选：直连模型 API（默认关闭，**按 AI 分别配置**）

直连不是"WinMon 自己的 AI"，而是给**你正在用的 AI** 准备的钥匙：
识别到智谱就找 `zhipu`，识别到 Claude 就找 `anthropic`，找不到就只用剪贴板交接。
**不会再出现"用户用 DeepSeek、WinMon 却调 GLM"的情况。**

```bat
set WINMON_AI_DIRECT=1
set WINMON_AI_API_KEY=...              :: 智谱 profile 用这个（只从环境变量读）
set WINMON_OPENAI_API_KEY=...          :: ChatGPT profile
set WINMON_ANTHROPIC_API_KEY=...       :: Claude profile
set WINMON_DEEPSEEK_API_KEY=...        :: DeepSeek profile
py winmon.py --ai-ask "帮我看看刚刚为什么卡"   :: 用 active profile 直接问
py winmon.py --ai-explain                      :: 解释最近一条本地事件
py winmon.py --ai-assist                       :: 跟随当前 AI（见下）
```

配置文件 `winmon_ai_provider.json`（**不要放 key**）：

```json
{"follow_detected": true, "active": "zhipu",
 "profiles": {
   "zhipu":     {"kind":"zhipu","model":"glm-5.3","api_key_env":"WINMON_AI_API_KEY",
                 "exact_tokens":true,"enabled":true,"timeout":60},
   "openai":    {"kind":"openai","model":"gpt-4o-mini",
                 "api_key_env":"WINMON_OPENAI_API_KEY","enabled":true},
   "anthropic": {"kind":"anthropic","model":"claude-3-5-haiku-latest",
                 "api_key_env":"WINMON_ANTHROPIC_API_KEY","enabled":true},
   "deepseek":  {"kind":"openai","base_url":"https://api.deepseek.com/v1",
                 "model":"deepseek-chat","api_key_env":"WINMON_DEEPSEEK_API_KEY",
                 "enabled":true}
 }
}
```

- `follow_detected: true`（默认）：助手按**当前识别到的 AI** 找 profile；
  找不到就只做剪贴板交接（无网络请求、无 token）。
- `active`：只给 `--ai-ask` 与 MCP 精确分词用，不参与"跟随"。
- `follow_detected: false`：才退回"固定用 active"的旧行为。
- 直连是**唯一能拿到供应商账单口径**的模式（响应里的 `usage`）；
  MCP 侧可以开 `exact_tokens` 用分词器精确到模型，但两者都不等于客户端整段对话的账单。
- 智谱走 OpenAI 兼容端点 `https://open.bigmodel.cn/api/paas/v4/chat/completions`，
  已实测 `prompt_tokens / completion_tokens` 与正文都正确。

### AI 助手：跟随你正在用的 AI（阶段 6 / 8）

AI 工作区 →「打开助手…」打开窗口（或 `--ai-assist`）。**助手窗口只做四件事**：
看接入/时段状态、把现场交给 AI、让搭子说一句、保存回复；不再塞 API key、值守、接入说明。

- **跟随当前 AI**：识别到谁就找谁自己的直连 profile；
  有 key 就调用它并显示 `输入 / 输出 = 总 token（API 回执）`；
  **没有该 AI 的 key / profile 时，把现场复制到剪贴板**，你粘到它的对话里即可；
  **绝不回退到另一个模型**。
- **没有直连就不自动跑**：值守/自动解释只在**主动 AI** 模式、当前 AI 直连可用时才调用；
  只读/本地模式绝不自动调用，也不会拿别的模型顶替。
- **手动「搭子说一句」**：点一下才跑一次。主动 AI + 有 key 时直连一次并记 token；
  否则用本地兜底按人设/检测到的应用名说一句（0 token）。
- **「接入 AI」窗口**（AI 工作区 →「打开接入…」）：
  1. **MCP 接入（蓝色高亮，推荐）**：状态 + 「复制配置」常驻，
     JSON 片段和详细步骤默认折叠在「查看配置与步骤」里；
  2. **直连 API key（琥珀色高亮，可选）**：默认收在「高级」里，展开后先选
     “直连对象”（默认是占位项，
     不预绑定厂商；选跟随当前 AI 或手动智谱 / OpenAI / Claude / DeepSeek 后才出现
     key 输入框），**不会默认写死某个厂商的 key**；
     key 只放环境变量，本次运行临时输入也不写盘；
     “不要写进仓库/文档/对话”用红色粗体常驻；
  3. **独立工作区（可选）**：给新项目单独建工作区/新对话，避免旧上下文串味；
     选文件夹/打开/复制建议常驻，长解释折叠；
  4. AI 行为：人设（关心/损友/安静/自定义导入，可复制到 AI 自定义指令）、
     读取媒体/游戏应用名、读取浏览器标题、允许提醒；值守/自动解释折叠在
     “主动 AI 的额外动作（会花 token）”里；
  5. 主动搭子（C，默认关）：总开关常驻，专注/会议/夜深三个独立允许开关 +
     每日上限/最短间隔折叠在“调整场景、频率与上限”里。
  顶部状态条用绿色/琥珀色直接标明“接上了没有”，不用在文字里找。
- **本地记录** `winmon_ai_chat.jsonl`：
  - 直连：问题 + 回答 + 真实 token；
  - 剪贴板交接：问题 + “WinMon 看不到这次回复”；
  - 「保存 AI 回复」：你把 AI 的回答复制到剪贴板后点一下，回复就存进本地记录。
  这样**关掉 AI 的对话窗口后，WinMon 这边仍有交接/回答留痕**；「记录…」单独查看。
- **网页端（智谱 / ChatGPT / Claude 等）的对话记录仍在它们自己的账号里**，
  WinMon 读不到；它只能记录“我交给了它什么”和“你粘回来的回答”。

`winmon_ai_assist.json`（模式、提醒、人设、工作区，**不进仓库**）：

```json
{"mode":"local","break_enabled":true,"workspace_dir":"",
 "persona_tone":"care","persona_custom":"",
 "read_media":true,"read_game":true,"read_web_title":true,
 "proactive_enabled":false,"allow_focus":false,"allow_meeting":false,
 "allow_night":false,"proactive_max_per_day":3,"proactive_min_interval":1800,
```

窗口标题等文本一律先过 `sanitize_untrusted`；**伴侣素材**只发前台应用类型、
媒体/游戏**应用名**、浏览器**网页标题**；**不发曲名/歌手、非浏览器标题、截图、
文件路径、键盘输入**。你主动点「交给 AI」时，会另发一份当前窗口清单（含标题）
用于判断哪个程序卡住；这份快照只在这次操作里发出。所有开关都在「接入 AI」窗口里，随时可关。

### 语言（中文 / English）

设置 →「语言 / Language」可选中文或 English，保存在 `winmon_settings.json` 的
`language` 字段。切换后：

- 主界面静态文案、五个标签页标题、AI 状态条与 AI 窗口立即重译；
- 设置/助手/接入窗口按当前语言重建；
- AI 的角色说明、提醒、剪贴板提示词也跟随语言（`time_slot(..., lang=...)`）。

详细说明：`winmon_i18n.py` 用中文原文查表 + 反向表，动态数据（窗口标题、计数、
状态栏）保持原样；未进表的细节文案会保持中文，不会显示成乱码或空白。

### 界面颜色（普通 / 深色）

设置 →「界面颜色」：

| 选项 | 行为 |
| --- | --- |
| **普通（白底）** | 纯白页面 + 深色文字；媒体/AI/接入高亮卡是浅色 |
| **深色（黑底）** | 纯黑页面 + 白字；标题栏同步变深；高亮卡换成同色系深底亮字 |

保存后**立即重建主界面**，不需要重启；颜色存进 `winmon_settings.json` 的
`theme` 字段（`light` / `dark`）。**没有「跟随系统」选项**：旧设置里若还存着
`system`，启动时按普通（白底）处理，可再手动选深色。深色下媒体行右侧的
**上一首 / 播放暂停 / 下一首**使用自定义圆角按钮（深绿底白字），
不会和彩色卡片或黑色页面糊成一块；主界面其它动作按钮也统一为圆角样式。

### 字号大小（设置里可调）

设置 →「字号大小」：9 / 10 / 11 / 12，**默认 9，最小 9**。
上限 12 不是随意定的：在最小窗口 1080×660 下实测，12 号仍能完整显示；
再大媒体行和顶部工具条就会被压出省略号。
保存后**当场生效**，主界面、AI 助手、接入窗口、设置窗口和弹窗
一起变，不需要重启；同时会把 `font_size` 写进 `winmon_settings.json`，下次启动沿用。
媒体行字符宽度和播放器下拉框会随字号收窄，避免 12 号字把播放按钮挤出屏幕。

**目前仍没有的**：MCP 写工具（关窗/结束进程/截图，按安全边界暂不开放）、
完整 Streamable HTTP 的 SSE / 订阅、`resources` / UIA 地址栏。
完整方案与取舍见 [`MCP.md`](MCP.md) §十。

## 九、测试

`tests/` 下是一套**可重复运行的验证用例**（986 个），只用 Python 标准库

  用来目视确认图标清晰度（界面截图里抓不到 Tk 画的图片）。
  ```bat
  py tests\icon_montage.py 32 4           :: 32×32 图标放大 4 倍拼成一张图
  py tests\icon_realsize.py 16,24,28,32   :: 按真实显示像素对比不同尺寸
  ```
- `tests/av_latency_test.py` / `av_compare.py`：**音频延迟测量**（扬声器放咔声、
  麦克风录回，算延迟毫秒数）。用于排查"音画不同步"到底是音频侧还是视频侧。
  ```bat
  py tests\av_latency_test.py 5           :: 对当前默认输出测 5 次
  py tests\av_compare.py --list           :: 列出可指定的输出设备
  py tests\av_compare.py --device 0 1 -n 4 :: 逐个设备测（不改系统默认设置）
  ```
  **注意**：该工具测的是"播放→听到"的**总**时间，里面包含**麦克风侧的固定开销**
  与播放起点的不确定性，所以**绝对值不可采信、单次结果抖动较大**；
  它适合做的判断是"同一台机器上两个输出设备之间的**差值**"。
  检测器本身有单元测试（`test_a8_av_latency.py`）保证不会把回声/噪声误判成咔声。
- `tests/make_icon.py` / `make_shortcut.py`：生成程序图标与桌面快捷方式。
  ```bat
  py tests\make_icon.py                   :: 生成 winmon.ico
  py tests\make_shortcut.py               :: 在桌面创建快捷方式
  py tests\make_shortcut.py --remove      :: 删除桌面快捷方式
  ```
- `tests/lint_check.py` 是**代码复检器**（不属于测试）：用 AST 找未使用的 import、
  重复定义、疑似死代码、遗留标记与过长函数，不引入任何第三方库。
  ```bat
  py tests\lint_check.py                  :: 新增问题 0 则退出码 0
  ```
  它的"疑似死代码"是**跨文件**判定的（`winmon_core` 的公共 API 由 `winmon.py` 调用，
  所以不算死代码）；确实要保留的例外写在 `tests/lint_baseline.txt`，每行必须写理由，
  问题修掉后还会提醒你删掉那一条（**当前这份清单是空的** —— 以前那条
  `resolve_shortcut()` 已随死代码清理删除）。`test_a9_lint_check.py` 守着这些判据，
  并且有一条"真实项目当前没有新增问题"的元检查 —— 往项目里加一段没人用的代码，
  整轮测试就会变红。

## 十、清理程序文件

程序运行时会在**用户数据目录**里生成几个文件（目录缓存、错误日志、字节码缓存、
你导出的操作记录）。那个目录在哪、为什么不在程序目录里，见
[十一、文件说明](#十一文件说明)。
清理入口在**左侧列表右键 →「清理程序文件…」**（弹窗逐项勾选、显示文件数与大小），
命令行是 `py winmon.py --clean`（只列出）与 `py winmon.py --clean --yes`（清理）。

**清单一共 8 项**（下面就是全部 —— 界面里也是这 8 项）：

| 清理项 | 默认勾选 | 说明 |
| --- | --- | --- |
| 程序目录缓存 `winmon_catalog.json` | ✅ | 删掉后下次重新扫描系统（约 0.4 秒），不影响任何设置 |
| 错误日志 `winmon_error.log` | ✅ | 只在启动失败时生成 |
| 字节码缓存（主程序）`__pycache__/` | ✅ | 解释器会自动重建 |
| 字节码缓存（测试）`tests/__pycache__/` | ✅ | 解释器会自动重建（这两项在**程序目录**里，其余都在用户数据目录） |
| 导出的操作记录（系统临时目录） | ✅ | 「导出操作记录」生成的 `winmon_history_*.txt` |
| 媒体会话快照 `winmon_media.jsonl` | ✅ | 常驻媒体助手每 3 秒写一行的运行缓存，下一次写入会自动重建 |
| **操作历史日志 `winmon_history.log`** | ❌ | **这是留痕记录**（谁在什么时候被关闭/结束了）：删掉就没了。只想清掉界面上的列表请用「操作历史…」窗口里的「清空列表」 |
| **`winmon_settings.json`** | ❌ | **你的用户数据**：收藏 / 手动分类 / 最近使用 / 界面偏好 |

**安全约定**：只清**程序自己产生的**文件；真正删除时只删清单里解析出来的路径
（这个入口不接受任意路径参数，所以不可能删到别的东西）；用户数据默认不勾选、
界面上写明风险，命令行要清它得显式加 `--settings`。

这些文件**都在 `.gitignore` 里**，不会被误当成源文件提交进版本库。

## 十三、隐私：它会不会把你的东西发出去？

**不会。** WinMon 是**纯本地**工具：

| 事实 | 说明 |
| --- | --- |
| 零第三方依赖 | 只用 Python 标准库与 Windows 自带组件（`test_a6` 会拦住任何新增的第三方 import） |
| 不联网 | **默认没有任何网络请求**（不发遥测、不回传）。只有三条**显式开启**的路径会联网：① `WINMON_AI_DIRECT=1` 的直连模型 API（含「AI 助手」）；② 你自己给 `--mcp-http` 配的隧道；③ `exact_tokens=true` 时把 MCP 工具结果发给智谱分词器计数。三者默认关闭，不开就不存在 |
| 数据留在本机 | 窗口标题、进程路径、操作历史都只写进**你自己的**用户数据目录，不离开这台电脑（除非你显式开上面三条） |
| 屏幕画面 | 只有你**主动看**的时候才抓取，只显示在界面上，不落盘、不外发；**MCP 没有截图工具**；AI 助手也不发截图 |
| 需要留意的 | `winmon_history.log` 里会记**窗口标题**（可能含文件名、网页标题）。要分享日志前先看一眼内容；它已经在 `.gitignore` 里，不会被误提交 |

**关于 AI 接入**：MCP 层是**只读**的（四个工具：主 AI / 本地事件 / 剧本 / 预算状态），
没有截图、没有键盘鼠标、没有结束进程。
但只要你把上下文交给 AI（桌面 MCP、HTTP/隧道、剪贴板桥、或「AI 助手」），
**窗口标题与事件证据就会离开本机**——所以设计上：默认不调模型、
直连要显式设环境变量、HTTP 只绑回环并要 Bearer token、隧道按需开启、
AI 助手默认关闭且**只跟随当前 AI**（没有对应 key 就只复制到剪贴板，不联网）、
恢复预算只能在本机操作。
窗口标题始终被当作**不可信输入**清洗（提示注入）。
